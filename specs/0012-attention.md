# 0012 — Не пропустить: звук, уведомления, трей

- **Status:** Draft
- **Issue:** #57

## Проблема

Звонок и сообщение сейчас видно, только если окно Aster открыто и на экране. Клиент ничем не привлекает внимание: нет звука вызова, нет системного уведомления, нет значка в трее, а закрытие окна убивает процесс вместе с соединением. Для сервиса на двоих это ломает основной сценарий — позвонить человеку, который не смотрит в окно.

## Предлагаемое решение

### Что звучит и когда

| Событие | Звук | Уведомление |
|---|---|---|
| `call-state: ringing` | рингтон, повтор до конца `ringing` | «Кент звонит» с действиями |
| `call-state: calling` | гудок вызова, повтор | — |
| `call-state: connected` | короткий подтверждающий сигнал | — |
| `call-state: ended` | короткий сигнал завершения | — |
| `message-upserted` (входящее, окно не в фокусе) | короткий сигнал | «Кент: <начало текста>» |

- Звуки — синтезируются в UI через WebAudio (осциллятор + огибающая), без аудиофайлов в бандле: два-три тона достаточно, а бандл не растёт и лицензий не тянет.
- Звук не играет, когда его источник — свой же звонок в `connected` (идёт разговор), и когда окно в фокусе для входящего сообщения.
- Рингтон звучит и при свёрнутом в трей окне: webview жив, пока окно скрыто, а не закрыто.

### Системные уведомления

`tauri-plugin-notification`. Разрешение спрашивается один раз при первом показе; отказ не ломает ничего, кроме самих уведомлений.

- Уведомление о входящем звонке показывается всегда, о сообщении — только когда окно не в фокусе.
- Клик по уведомлению поднимает и фокусирует окно (`show` + `set_focus` + `unminimize`).
- Текст сообщения в уведомлении обрезается до 120 символов.

### Трей и жизнь окна

`tauri::tray::TrayIcon` с меню: «Открыть», «Выйти».

- Закрытие окна (крестик WM) **прячет** его в трей, а не завершает процесс: соединение с сервером и звонок остаются живыми. Выход — только через пункт меню трея или `Ctrl+Q`.
- Клик по значку трея переключает видимость окна.
- Значок меняется, когда есть непрочитанное: обычный / с точкой. Счётчик не нужен — собеседник один.
- Тултип значка повторяет состояние соединения из `0009`.

### Непрочитанное

Ядро не знает, что пользователь увидел. «Прочитано» = окно в фокусе и открыт чат (не экран настроек). UI сообщает ядру о фокусе командой `set_window_focused { focused }`, ядро считает непрочитанные и эмитит `unread { count }` — это же значение красит значок трея.

### Команды и события

| Команда | Аргументы | Результат |
|---|---|---|
| `set_window_focused` | `{ focused: bool }` | `()` |
| `focus_window` | — | `()` — поднять и сфокусировать окно |

| Событие | Payload |
|---|---|
| `unread` | `{ count: u32 }` |

## Альтернативы

- **Звуки файлами (ogg/wav) в бандле** — отклонено для v1: WebAudio даёт нужные сигналы парой осцилляторов, а файлы тянут за собой вопрос лицензии и лишние килобайты. Если понадобится настоящий рингтон — это замена одного модуля.
- **Звук из ядра (`rodio`)** — отклонено: ещё один аудиовыход помимо `cpal` из `0011`, конкурирующий за устройство. В webview звук живёт рядом с UI, который и решает, когда звучать.
- **Закрытие окна завершает приложение** — отклонено: тогда «в фоне» не существует, и звонок дойдёт, только если окно открыто, то есть проблема из постановки не решается.

## Затронутые компоненты

- `crates/client/src-tauri` — трей, перехват закрытия окна, `tauri-plugin-notification`, счётчик непрочитанного.
- `crates/client` — WebAudio-сигналы, отслеживание фокуса, показ уведомлений.

## Открытые вопросы

- Нужна ли настройка «беззвучно» в v1, или достаточно системного mute? Предлагается отложить: экран настроек сейчас только про подключение.

# 0013 — Настройки голоса: устройства, эхо- и шумоподавление, push-to-talk

- **Status:** Accepted
- **Issue:** #64

## Проблема

В `0011` звонок работает, но:

- нет эхоподавления — без наушников собеседник слышит себя;
- нет шумоподавления — клавиатура и вентилятор идут в эфир;
- микрофон открыт всегда (VAD с фиксированным порогом), push-to-talk нет;
- устройства только системные по умолчанию — не переключить звук на наушники, не сменив устройство в системе.

Нужны настройки голоса, как в Discord: устройства ввода и вывода, обработка звука, режим ввода.

## Предлагаемое решение

### Настройки

Файл `voice.json` в `app_config_dir` (рядом с `settings.json` из `0009`). Отсутствующий или битый файл — значения по умолчанию, незнакомые поля игнорируются.

```json
{
  "input_device": null,
  "output_device": null,
  "echo_cancellation": true,
  "noise_suppression": "standard",
  "auto_gain": true,
  "input_mode": "voice_activity",
  "vad_threshold_dbfs": -45,
  "ptt_release_delay_ms": 200,
  "ptt_shortcut": null
}
```

| Поле | Значения | По умолчанию |
|---|---|---|
| `input_device`, `output_device` | `id` устройства из `list_audio_devices`, `null` — системное по умолчанию | `null` |
| `echo_cancellation` | `bool` | `true` |
| `noise_suppression` | `"off"` \| `"standard"` \| `"strong"` | `"standard"` |
| `auto_gain` | `bool` | `true` |
| `input_mode` | `"voice_activity"` \| `"push_to_talk"` | `"voice_activity"` |
| `vad_threshold_dbfs` | −70…−20 | −45 |
| `ptt_release_delay_ms` | 0…1000 | 200 |

Значения вне диапазона приводятся к границе.

### Устройства

- `list_audio_devices` перечисляет устройства ввода и вывода через `cpal`: `{ id, name, is_default }`. `id` — стабильный идентификатор `cpal` (`DeviceId`), `name` — человекочитаемое описание.
- На Linux `cpal` собирается с фичей `pulseaudio` (чистый Rust, работает и поверх PipeWire): `default_host()` предпочитает PulseAudio-хост и отдаёт устройства с нормальными именами (`Raptor Lake … Speaker`, мониторы выходов как входы). ALSA-хост без неё показывает сырые `hw:CARD=0,DEV=6`; он остаётся фолбэком, если звукового сервера нет.
- Сохранённое устройство не найдено (отключили наушники) — берётся системное по умолчанию, эмитится `call-audio-error` с понятным текстом. Настройка при этом **не** сбрасывается: когда устройство вернётся, оно снова будет использоваться со следующего звонка или смены настроек.
- Смена устройства во время звонка применяется сразу: перезапускается только затронутый поток (захват или воспроизведение), звонок не рвётся.

### Обработка звука

Цепочка захвата в ядре, 48 kHz моно:

```
микрофон ─► кадры 10 мс ─► AEC3 ─► NS ─► AGC2 ─► RNNoise ─► VAD/PTT-гейт ─► Opus (20 мс)
                            ▲
воспроизведённый звук ──────┘ (референс для AEC)
```

- **`aec3`** (порт WebRTC AudioProcessing на чистом Rust, MIT/BSD): конвейер `linear` — high-pass фильтр, эхоподавление AEC3, шумоподавление WebRTC NS, автоусиление AGC2. Каждый блок включается по своей настройке, HPF всегда.
- **Референс эха** — ровно те кадры, что ушли в динамик: воспроизведение отдаёт каждый кадр в канал обработки захвата, та перед каждым кадром микрофона скармливает AEC накопленный рендер. Задержку между ними AEC3 оценивает сам.
- **`noise_suppression`:** `standard` — WebRTC NS внутри `aec3`; `strong` — WebRTC NS выключен, вместо него `nnnoiseless` (RNNoise, чистый Rust) после AEC. RNNoise лучше давит нестационарный шум (клавиатура), но сильнее окрашивает голос — поэтому это опция, а не умолчание.
- **Замеры** (release, синтетика): эхо −19.5 → −97 dB при сохранении ближнего голоса; стационарный шум −31 → −41 dB (WebRTC NS) и −31 → −59 dB (RNNoise); стоимость 0.16 мс и 0.04 мс CPU на кадр 10 мс.
- Обработка идёт в отдельном потоке `aster-dsp`, а не в аудиопотоке `cpal` и не в задаче кодирования: граф `aec3` построен на `Rc` и не `Send`, в tokio-задачу его не положить. Колбэки устройства только копируют кадры в ограниченный канал этого потока (захват и рендер — один канал, порядок сохраняется); переполнение — кадр отбрасывается, аудиопоток не блокируется. Обработанные кадры идут в кодировщик.
- `echo_cancellation: false` — потоку не подаётся референс рендера, AEC3 без референса пропускает звук как есть.
- В `dev`-профиле `aec3` и `nnnoiseless` собираются с `opt-level = 3`: без этого конвейер в debug тратит ~4 мс на кадр 20 мс, в тестах и `cargo tauri dev` — впритык к реальному времени.
- Тестовый сигнал для AEC должен быть широкополосным: на скользящем узкополосном тоне AEC3 сходится только на уже звучавших частотах и пропускает эхо на новых. Реальная речь широкополосная; unit-тест использует шум с огибающей слогов (эхо −23 → −69 dB).
- Настройки обработки меняются во время звонка: конвейер пересоздаётся на лету (AEC переобучится за секунды).

### Режим ввода

Передаётся ли голос, решает гейт перед Opus. При закрытом гейте кодируется тишина, как при mute (`0011`).

| Режим | Гейт открыт |
|---|---|
| `voice_activity` | VAD после обработки выше `vad_threshold_dbfs` (с удержанием 300 мс из `0011`) |
| `push_to_talk` | клавиша нажата, плюс `ptt_release_delay_ms` после отпускания — чтобы не обрезать конец слова |

`muted` сильнее режима: при mute гейт закрыт всегда.

- Удержание считается кадрами: `ceil(ptt_release_delay_ms / 20)` кадров после отпускания.
- В `push_to_talk` при нажатой клавише уходит всё, что слышит микрофон, VAD гейт не закрывает (тихая речь не режется).
- `local_speaking` из `0011` теперь значит «VAD слышит голос **и** он уходит собеседнику»: в PTT без нажатия индикатор не горит.

### Клавиша push-to-talk

Нажатие приходит из двух источников, гейт открыт, если нажато в любом:

1. **Окно в фокусе:** UI ловит `keydown`/`keyup` выбранной клавиши и вызывает `set_push_to_talk { pressed }`. Работает везде. Клавиша хранится в UI (`localStorage`), ядру она не нужна. `set_window_focused { focused: false }` отпускает этот источник: отпускание вне окна до UI не дойдёт.
2. **Глобально:**
   - **Linux Wayland** — портал `org.freedesktop.portal.GlobalShortcuts` (через `ashpd`). Ядро регистрирует шорткат `push-to-talk` с описанием «Push-to-talk» и получает `Activated`/`Deactivated` как нажатие и отпускание. Саму клавишу назначает пользователь в композиторе: в GNOME/KDE система показывает диалог, в Hyprland — строка в конфиге:
     ```
     bind = , mouse:276, global, :push-to-talk
     ```
     `mouse:276` — боковая кнопка мыши, для клавиатуры, например, `bind = , F13, global, …`. Префикс перед `:` — app id. Хост-приложение (не flatpak) сообщает его порталу через `org.freedesktop.host.portal.Registry`, а тот принимает id, только если установлен `dev.gemshrine.aster.desktop`. Без него (dev-сборка, бинарник без пакета) id пустой и бинд — `global, :push-to-talk`; с установленным desktop-файлом — `global, dev.gemshrine.aster:push-to-talk`. Проверено в Hyprland: `hyprctl globalshortcuts` показывает шорткат, `hyprctl dispatch global :push-to-talk` доходит до ядра как `Activated`.
   - **X11, Windows, macOS** — `tauri-plugin-global-shortcut` с сочетанием из поля `ptt_shortcut` (`"F13"`, `"Alt+Space"` …). Глобальный хук получает нажатие и отпускание. На Wayland этот путь не используется: X11-перехват там клавиш не видит. Плагин подключается в `setup` и только не на Wayland: без X-дисплея его инициализация падает, и приложение не должно из-за этого не запуститься.
   - Если глобальный источник недоступен (нет портала, сочетание занято), работает только режим окна, UI показывает предупреждение из `push-to-talk-status`.
   - Глобальный источник регистрируется только в режиме `push_to_talk`: в GNOME/KDE привязка открывает системный диалог, и пользователю VAD он не нужен. В `voice_activity` статус — `unavailable` с `reason: "push-to-talk is off"`, сессия портала закрывается, сочетание снимается.

Поле в `voice.json` для не-Wayland: `"ptt_shortcut": "F13"` (`null` — глобальной клавиши нет).

### Команды Tauri

| Команда | Аргументы | Результат |
|---|---|---|
| `list_audio_devices` | — | `{ inputs: Device[], outputs: Device[] }`, `Device = { id, name, is_default }` |
| `get_voice_settings` | — | `VoiceSettings` |
| `set_voice_settings` | `{ settings: VoiceSettings }` | `VoiceSettings` (после нормализации); применяется сразу, в том числе во время звонка |
| `set_push_to_talk` | `{ pressed: bool }` | `()` |
| `push_to_talk_status` | — | `PushToTalkStatus` |

### События Tauri

| Событие | Payload |
|---|---|
| `call-audio` | из `0011` плюс `transmitting: bool` — гейт открыт и не muted |
| `push-to-talk-status` | `{ global: "portal" \| "shortcut" \| "unavailable", reason: string \| null }` — при старте и смене настроек |
| `input-level` | `{ dbfs: f32 }` — уровень после обработки, 10 раз в секунду, только пока открыт экран настроек (`set_input_monitor { enabled }`) |

Индикатор уровня (`input-level`) нужен для настройки порога, как полоса в Discord. Мониторинг включается командой `set_input_monitor { enabled: bool }`: вне звонка он открывает микрофон с той же обработкой, но без отправки; в звонке — просто публикует уровень.

## Альтернативы

- **`webrtc-audio-processing`** (биндинги к C++ WebRTC APM) — тот же алгоритм, но сборка тянет meson/ninja и C++-тулчейн на каждой машине. `aec3` даёт порт на чистом Rust, что соответствует решению `0011` про `opus-pure`.
- **Только RNNoise** — не решает эхо. **Только WebRTC NS** — хуже с нестационарным шумом. Поэтому оба, выбором пользователя.
- **`evdev` для глобальной клавиши на Linux** — работает в любом окружении, но требует доступа к `/dev/input` (группа `input`), то есть к любому нажатию в системе. Портал даёт то же без такого доступа.
- **Свой хоткей через `tauri-plugin-global-shortcut` на Wayland** — не работает: плагин использует X11-перехват.

## Затронутые компоненты

- `crates/client/src-tauri` — `core::voice` (устройства, конвейер обработки, гейт, PTT), команды, события, зависимости `aec3`, `nnnoiseless`, `ashpd`, `tauri-plugin-global-shortcut`.
- `crates/client/src` — экран «Голос» в настройках, локальная клавиша PTT, индикатор «говорю» по `transmitting`.

# 0005 — Голосовые звонки

- **Status:** Accepted
- **Issue:** —

## Проблема

Нужен голосовой звонок 1:1 поверх WebRTC, с приемлемым качеством на слабом железе/сети и без лишней сложности UI (только два человека, не нужен полноценный "звонковый" продукт).

## Предлагаемое решение

### Установление звонка

1. Инициатор жмёт "Call" в UI → клиент создаёт `RTCPeerConnection` (`webrtc-rs`), добавляет локальный аудио-трек, генерирует SDP offer, шлёт через `Signal { Offer }`.
2. Получатель видит входящий звонок (уведомление в UI) → при принятии создаёт свой `RTCPeerConnection`, отвечает `Signal { Answer }`.
3. Оба обмениваются ICE-кандидатами через `Signal { IceCandidate }` по мере их появления (trickle ICE).
4. После установления DTLS/SRTP — аудио идёт напрямую P2P (или через `coturn`, если прямое соединение не удалось).
5. Любая сторона может завершить звонок — `Signal { CallEnd }`, закрытие `RTCPeerConnection` с обеих сторон.

`RTCPeerConnection` создаётся с `ice_servers` из последнего `Welcome` (`0003`). TURN-креды временные (24h) — при переподключении к сигналинг-серверу клиент получает новые.

### Аудио

- Кодек: Opus (стандарт для WebRTC voice, хорошо ведёт себя на плохих сетях).
- Echo cancellation / noise suppression — полагаемся на то, что предоставляет `webrtc-rs`/аудио-бэкенд ОС (например, через `cpal` + WebRTC's built-in processing, если доступно); если `webrtc-rs` не даёт AEC "из коробки" — фиксируется как известное ограничение v1, не блокер.
- Захват/воспроизведение звука — `cpal` (кроссплатформенный аудио ввод/вывод), интеграция с треком `webrtc-rs`.

### Режим передачи голоса

v1: **voice-activity (всегда открытый микрофон с локальным VAD)** как дефолт, с ручным mute-toggle. Push-to-talk — как опция в настройках (хоткей через Tauri global shortcut), не как единственный режим — оба варианта дёшевы в реализации поверх одного и того же аудио-трека (управляют только тем, включен ли трек).

### UI-состояния звонка

`Idle -> Calling (outgoing) / Ringing (incoming) -> Connected -> Ended`. Таймаут на `Calling`/`Ringing` (например 30s) → авто-`CallEnd`.

## Альтернативы

- **Постоянно открытый голосовой канал (как Discord-войс-чат)** вместо звонков по запросу — рассматривалось, но отклонено для v1: звонок по запросу проще в реализации (нет постоянного WebRTC-соединения, меньше состояний) и достаточен для двух человек, которые созваниваются осознанно. Можно добавить позже как отдельный режим без изменения транспортной части.
- **Video** — не в v1 (`0001`), но `RTCPeerConnection`/протокол не мешают добавить видео-трек позже.

## Затронутые компоненты

- `crates/client` — WebRTC peer management, аудио захват/воспроизведение, UI звонка.
- `crates/protocol` — `SignalPayload` уже описан в `0003`.

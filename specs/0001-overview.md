# 0001 — Обзор проекта и цели

- **Status:** Accepted
- **Issue:** —

## Проблема

Нужен приватный сервис для текстового и голосового общения между двумя конкретными людьми (владелец репозитория и Кент), который:

- разворачивается на недорогом VPS (1 vCPU / 1 ГБ RAM класса — ориентир, не жёсткое требование, но сервер не должен требовать больше);
- не зависит от сторонних SaaS (Discord/Zoom/Telegram) — приватность и контроль;
- не должен ресинтезировать Discord целиком — фокус на двух людях, без ролей, серверов-гильдий, сотен фич.

## Цели (must have)

1. Текстовый чат 1:1 в реальном времени с локальной историей у каждого клиента.
2. Голосовой звонок 1:1 (push-to-talk и/или voice-activity, решается в отдельной спеке) на WebRTC/Opus.
3. Десктопный клиент на Tauri (Linux/Windows/macOS — минимум Linux, т.к. на нём разрабатываем).
4. Сервер сигнализации, разворачиваемый на VPS через Docker Compose, с TLS.
5. Аутентификация только для двух известных пользователей — не публичная регистрация.

## Не цели (out of scope, минимум для v1)

- Групповые звонки / чаты (>2 человек).
- Видео (только голос в v1; видео — возможное расширение позже, инфраструктура WebRTC это не исключает).
- Мобильные клиенты.
- Федерация с другими серверами / другими протоколами (Matrix и т.п.).
- E2E-шифрование чата сверх TLS в v1 (см. `specs/0006-auth-security.md` для обсуждения, может стать отдельной фичей).

## Компоненты верхнего уровня

- `crates/protocol` — общие типы сообщений сигналинга и чата (сериализация через `serde`/`bincode` или JSON — решается в 0003).
- `crates/signaling-server` — сервер на `axum`, держит WebSocket-соединения обоих пользователей, релеит SDP/ICE и чат-сообщения, не хранит голосовой трафик.
- `crates/client` — Tauri-приложение с Leptos-фронтендом: UI чата, управление звонком, локальная БД истории.
- `deploy/` — docker-compose (signaling-server, caddy, coturn), конфиги.
